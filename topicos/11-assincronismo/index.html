Assincronismo: timers, Promises, fetch e async/await

Algumas tarefas demoram (esperar um timer, buscar dados na internet). O JavaScript não trava a página esperando: ele "deixa agendado" e continua o resto do código.

1. Timers: setTimeout e setInterval

Repare na ordem em que as mensagens aparecem — a 2ª vem antes da 3ª, mesmo estando "depois" no código.

2. Promises

Uma Promise representa um valor que ainda vai chegar. Ela termina de duas formas: resolve (deu certo → .then) ou reject (deu erro → .catch).

3. async / await

A forma moderna e mais legível de usar Promises: o código parece sequencial. await só pode ser usado dentro de uma função async.

4. fetch — buscando dados de uma API

fetch devolve uma Promise. Use try/catch para tratar falhas e confira resposta.ok (um erro 404 não cai no catch sozinho!).

5. Promise.all — várias tarefas ao mesmo tempo

📌 Resumo
  • setTimeout roda uma vez depois de X ms; setInterval repete (pare com clearInterval).
  • Promise: .then() sucesso · .catch() erro · .finally() sempre.
  • async/await + try/catch deixa o código assíncrono parecer síncrono.
  • Promise.all([...]) espera várias tarefas em paralelo.

🧪 Desafio

Crie uma função async que espera 1 segundo, mostra "Pronto!" e retorna o número 42.

Ver uma solução 
const esperar = (ms) => new Promise(r => setTimeout(r, ms));

async function tarefa() {
  await esperar(1000);
  console.log('Pronto!');
  return 42;
}

tarefa().then(valor => console.log('Retornou', valor));
